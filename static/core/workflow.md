# 核心工作流

完整论文任务按以下顺序推进。

## 1. 建立问题台账

提取每个子问题、输入、输出、约束、数据来源和论文必须呈现的结果。如果无法建立问题台账，不要进入建模。

## 2. 建立数据台账

列出可用数据集、字段、单位、时间范围、空间范围、缺失情况、异常情况，以及每个数据集支撑的子问题。

## 3. 草拟模型路线

为每个子问题选择模型族，并说明它为什么匹配任务。模型路线必须包含变量、目标或评价逻辑、约束和检验计划。

## 4. 从证据向外推进分析

完成数据预处理、可视化、模型求解、结果可视化、敏感性分析和模型检验。整理中间文件，但把有效发现吸收进论文。

## 5. 按题目问题写作，而不是按代码顺序写作

论文应按赛题要求回答问题一、问题二、问题三。不要按照脚本运行顺序描述计算过程。

## 6. 检查结论与证据对应

对每个重要结论，找到对应支撑：

```text
Claim -> Data / formula / figure / table / validation / sensitivity result
```

Delete or weaken claims without support.

## 7. 汇总终稿

整合摘要、关键词、问题重述、问题分析、模型假设、符号说明、数据处理、模型建立、结果分析、敏感性分析、模型检验、模型创新、优缺点、结论、参考文献和附录。

## 8. 局部修订

用户要求修改时，优先只改受影响阶段或段落。若修改会破坏论文结构，先说明需要同步调整的结构，再重写。
