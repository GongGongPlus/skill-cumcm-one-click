# 深层参考：模型创新

## 读取时机

当 `static/fragments/stage/model-innovation.md` 不足以提炼可信创新点、区分创新与常规操作或撰写克制表述时，读取本文件。

## 目标

模型创新用于总结本文相较常规做法的改进。创新点必须真实、具体、可证明。不要把普通建模步骤包装成重大突破。

## 可提炼的创新方向

指标体系创新：

- 根据题目背景构建更贴合问题的指标。
- 区分正向、负向和适度指标。
- 引入能够反映实际约束的新指标。

模型组合创新：

- 将机理模型与数据驱动模型结合。
- 将预测模型与优化模型衔接。
- 将评价模型与决策模型结合。

约束设计创新：

- 将现实中的容量、成本、时间、公平性、风险等因素写入约束。
- 将原本模糊的管理要求转化为可计算约束。

特征工程创新：

- 构造具有明确现实含义的特征。
- 使用滞后项、增长率、密度、比例、空间距离等增强解释性。

鲁棒性创新：

- 对不确定参数设置情景分析。
- 引入扰动检验或稳健优化思想。
- 对结果稳定性进行系统讨论。

可视化创新：

- 用图表揭示关键结构、变化趋势或方案差异。
- 将复杂结果转化为可解释的决策依据。

## 创新写法

推荐表达：

```text
本文在传统……模型基础上，引入……因素，使模型能够更好地反映……。
```

```text
针对题目中……的特点，本文构建了……指标，从而提高评价结果的解释性。
```

```text
本文将……模型与……方法结合，先完成……，再进行……，形成了较完整的建模流程。
```

```text
为检验方案稳定性，本文对……参数进行扰动分析，增强了结论的可靠性。
```

## 禁忌

避免使用“首次提出”“完全解决”“显著优于所有方法”“具有极高准确率”“具有普适性”等无法证明的表述。除非有充分证据，否则不要夸大创新。

## 论文位置

模型创新可以单独成节，也可以写入“模型优缺点与改进”之前。若创新点较少，不要硬凑多个点。宁可写一到两个真实创新，也不要列出空泛条目。
