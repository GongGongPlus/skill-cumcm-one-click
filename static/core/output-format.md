# 输出格式

## 工作过程中

论文未完成前，如需汇报进展，保持简短：

```text
当前完成：
下一步：
风险或待确认：
```

除非用户要求，不要把所有中间表格、探索笔记或代码日志堆进对话。

## 最终交付

最终回答应提供完整论文，或提供完整论文文件路径。支撑代码、图表和附录只能在论文完成后作为辅助材料说明。

若最终交付为 Word 文档，正文中的数学公式必须是 Word 可渲染、可编辑且排版正确的公式对象。优先使用 LaTeX 数学表达式生成 Word/OMML 公式，不要把公式作为普通文本、截图或不可编辑图片插入，也不要把 `t_ij`、`sum_k` 等纯文本包进 `m:oMath` 伪装成公式。

若最终交付为 Word 文档，正文、题目、一级标题、二级标题、三级标题、表格、图注、页眉页脚的字体必须统一：中文使用宋体，英文与数字使用 Times New Roman。所有标题文字必须为黑色，不使用蓝色、灰色或其他强调色作为标题颜色。不得混用 Calibri、Arial、微软雅黑等默认字体，除非用户明确指定其他模板。生成 `.docx` 后应使用 `scripts/verify_docx_typography.py` 做结构检查。

最终论文正文页数必须服从当届官方规则；当前国赛默认不超过 30 页，且不能依靠附录、空白、原始数据堆叠或代码灌水凑页数。正文应在页数上限内充分容纳图表分析、公式推导、算法原理、模型检验、敏感性分析和结果解释。

论文图表数量和视觉密度应接近参考优秀论文。所有论文图表必须由 Python 绘图库生成，优先使用 matplotlib、seaborn、plotly、networkx、scipy 或 statsmodels 等可复现实证绘图库；不得使用 AI 生成海报、装饰性图片、截图式图表或手工拼贴图替代数据图。图表必须清晰、美观、编号连续、单位完整，并在正文中解释其支撑的结论。图表类型必须多样，不能整篇只用单一图型；配色必须统一、克制、专业，不能使用默认低质样式、彩虹色、低对比度、拥挤标签或明显“AI风格”的卡片/发光/大色块装饰。

模型章节必须写得足够详细。每个模型至少说明建模目的、适用原因、变量与参数、数据输入、公式结构、目标函数或评价函数、约束条件、求解步骤、算法底层原理、参数选择依据、输出含义、检验指标和局限边界。禁止只写“本文采用某模型/算法进行预测或优化”而不展开原理。

## 论文骨架

除非赛题需要调整，否则使用以下默认结构：

```text
题目
摘要
关键词
一、问题重述
二、问题分析
三、模型假设
四、符号说明
五、数据预处理与可视化分析
六、模型建立与求解
七、结果分析与可视化
八、敏感性分析
九、模型检验
十、模型创新
十一、模型优缺点与改进方向
十二、结论
参考文献
附录
```

## 终稿检查

- 原题每个问题都已回答。
- 每个模型都有明确目的。
- 每个关键结果都有解释。
- 每张图都有图注、单位和论文角色。
- 每张图后都有紧邻解释，说明关键现象、对应问题、支撑结论和现实含义。
- 正文页数符合当届官方上限（当前国赛默认不超过 30 页），且不是靠附录灌水。
- 图表数量充分，视觉效果接近参考优秀论文。
- 图表类型多样，至少覆盖趋势、分布、比较、关系、误差、贡献、热力或流程等多种表达。
- 图表全部由 Python 绘图库生成，且图中文字中文为宋体、英文与数字为 Times New Roman。
- 图表配色美观统一，具有论文统计图质感，图中文字、坐标轴、图例、标注不遮挡、不模糊、不拥挤，不能有 AI 海报感或默认截图感。
- Word 交付时，可用 `scripts/verify_docx_figures.py` 检查图片、图注和图后解释是否齐全。
- Word 交付时，可用 `scripts/verify_docx_typography.py` 检查正文和样式字体是否统一为中文宋体、英文 Times New Roman，并检查题目与各级标题是否为黑色。
- 模型章节包含足够公式、算法底层原理、求解步骤、变量解释、参数依据和检验逻辑。
- 敏感性分析支撑稳健性。
- 模型检验支撑可信度。
- 创新点具体且可辩护。
- Word 交付时，公式能在 Word 中正确显示且可编辑，下标、上标、分式、求和、范数等结构不能退化为代码样文本。
- 最终输出是一篇完整论文。
